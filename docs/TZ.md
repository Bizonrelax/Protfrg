## 1. Что такое `.tsv` — по-человечески

**TSV = Tab-Separated Values**, «значения, разделённые табуляцией». Это **обычный текстовый файл**, который открывается Блокнотом. Внутри — таблица: одна строка файла = одна строка таблицы, столбцы разделены символом табуляции (тот, что нажимается клавишей Tab). Первая строка — заголовки.

Вот так выглядит `_meta/fields.tsv` (↹ — это реальный TAB, не пробелы):

```
key↹value↹updated
programs↹Cognitosalticus|KeySaver↹2026-11-12
bots↹ChatGPT|Claude↹2026-11-12
targets↹системный промпт↹2026-11-12
```

Почему TSV, а не CSV: в CSV разделитель — запятая, а запятые в русском тексте на каждом шагу, поэтому приходится оборачивать ячейки в кавычки и удваивать кавычки внутри. TSV идёт другим путём — он просто **запрещает табуляцию и перевод строки внутри данных**, и никакого экранирования кавычек не нужно . Табуляцию ты в тексте почти никогда не набираешь, запятую — постоянно.

Три полезных свойства:

- **GitHub сам рисует `.tsv` как таблицу** с заголовками и поиском — то есть твои метаданные будут читаться прямо в браузере, без скачивания .
- Excel и LibreOffice открывают TSV корректно (двойной клик или «Импорт текста», разделитель — табуляция).
- Файл построчно сравнивается Git'ом: видно, какое поле какого протокола ты изменил и когда.

Ограничение одно: длинный многострочный текст в ячейку не влезет. Поэтому правило хранилища: **короткое — в TSV, длинное — в `.md`**, а в ячейке ссылка `@file:notes.md`.

## 2. Зависимости: дело не в деньгах

**JavaFX бесплатна и открыта.** Она под GPLv2 **с Classpath Exception** — эта оговорка как раз и позволяет использовать библиотеку в программе с любой своей лицензией, не открывая свой код . Платное у Gluon — только поддержка и мобильные сборки, сам JavaFX — нет . То есть ни платить, ни открывать твой код никто не заставляет.

Проблема в другом — в **весе и хрупкости**:

| Что тянет за собой зависимость | JavaFX | Swing |
|---|---|---|
| Входит в JDK | нет, вынесена из JDK начиная с 11, отдельный SDK  | да, часть JDK |
| Нативные библиотеки под каждую ОС | да, сборка платформенно-зависимая  | нет |
| «Один jar и всё» | нет, нужен module-path и SDK рядом | да |
| Первая сборка без интернета | нет, Maven тянет артефакты | да, тянуть нечего |
| Размер дистрибутива | +десятки МБ | 0 |
| Через 10 лет соберётся | зависит от версий и репозиториев | да, пока есть JDK |
| Лицензионные обязательства | приложить текст лицензии, следить за совместимостью | нет |

Итог: зависимость — это не расход денег, это **расход надёжности**. Ты хочешь программу, которая запускается с флешки в 2036 году. Ноль зависимостей это даёт.

**Зафиксировано: Swing.** UI-слой в ТЗ изолирован от хранилища — захочешь JavaFX, заменим только «лицо», файлы и логику не тронем.

## 1. Назначение и главная цель

Программа создаёт, хранит и предъявляет **протоколы** — тексты, которые Ти вставляет в программы, чаты и ботов, вместе с описанием, для чего они и куда их вставлять, и с любыми сопутствующими файлами.

**Главная цель, критерий успеха:** Ти не должен испытывать трудности при подборе нужного протокола. Нужный протокол находится за **три клика или один поиск** и попадает в буфер обмена **одним нажатием**.

## 2. Принципы

1. **Нулевая потеря данных.** При любом сомнении сохраняются обе версии. Ничего не удаляется автоматически.
2. **Файлы — источник истины.** Всё лежит в открытом виде: `.md` для текста, `.tsv` для таблиц. Производные файлы удаляемы.
3. **Переносимость копированием.** Ни одной записи вне портфеля, ни одного абсолютного пути в метаданных.
4. **Ноль зависимостей.** Только стандартная библиотека Java.
5. **Офлайн полностью.** Ни одного сетевого обращения, ни телеметрии, ни проверки обновлений.
6. **Читаемость вне программы.** Портфель понятен в Проводнике, в Блокноте и на GitHub.
7. **Единый язык.** Один термин — одно слово в интерфейсе, справке, коде и именах файлов.
8. **Правка не уходя с окна.** Настройка (в первую очередь ВП) делается на месте.

## 3. Единый язык

Термин **Ubiquitous Language** (Э. Эванс, DDD) по-русски — **единый язык**. Правило: одно понятие = одно слово, синонимы запрещены; слово из глоссария обязано совпадать с надписью в интерфейсе, заголовком справки, именем класса и именем файла.

## 4. Модель данных

**Протокол** — единственная сущность верхнего уровня. Состав:

- **Основное поле** — текст протокола. Хранится внутри (`_meta/protocol.md`) **или ссылкой** на вложение (`@file:myprompt.md`). Ссылка не создаёт дубликат: файл остаётся файлом Ти, программа показывает и правит его на месте.
- **Назначение** — **одно** на протокол, состоит из связного текста (`purpose.md`) и **неограниченного числа полей**. Поле может быть **многозначным** — этим закрываются «для каких программ», «для каких ботов», «куда вставлять».
- **Инструкции к применению** — текст (`instructions.md`) или ссылка на файл.
- **Вложения** — любые файлы в корне папки протокола, включая подпапки.

**Форма протокола — всегда папка.** Протокол «только текстом» — это папка с одним `protocol.md`. Отдельной «листовой» формы нет: один код-путь = меньше мест для потери данных. Одиночный `.md`, брошенный в `protocols/`, автоматически оборачивается в папку с новым ID.

### 5.1 Правила форматов

- Кодировка **UTF-8 без BOM**, перевод строки **LF**, файл заканчивается переводом строки.
- **TSV:** первая строка — заголовки; табуляция и перевод строки внутри ячейки **запрещены**; экранирование `\t`, `\n`, `\\`, `\|`; разделитель многозначных полей — `|`.
- Порядок столбцов фиксирован, строки сортируются по ключу — чтобы версии сравнивались построчно.
- Длинный текст — в `.md`, в ячейке ссылка `@file:относительный/путь.md`.
- Все пути в метаданных — **относительные**, от папки протокола или от корня портфеля.
- **Markdown:** обычный текст с простой разметкой (заголовки, списки, жирный, курсив, код, ссылки). Full-YAML не используется.

### 5.2 Схемы служебных таблиц

| Файл | Столбцы |

| `app/fields.tsv` | `key, label, type, dict, multi, required, default, order, in_table, filterable, tip_id, help_id` |
| `app/dicts/*.tsv` | `code, label, aliases, note, order` |
| `app/tooltips.*.tsv` | `id, short, long, keys, help_id, updated` |
| `app/criteria.tsv` | `id, label, query, order` |
| `app/counter.tsv` | `last_id` |
| `app/journal.tsv` | `ts, action, protocol_id, target, result, detail` (только дописывание) |
| `app/index/protocols.tsv` | `id, folder, title, status, programs, bots, targets, tags, updated, files, flags` |
| `app/index/files.tsv` | `protocol_id, path, size, mtime, sha256` |
| `_meta/card.tsv` | вертикальная таблица `key, value`: `id, title, created, updated, rev, main, purpose, instructions` |
| `_meta/fields.tsv` | `use, key, value, updated` (`use` всегда `main`, зарезервировано под будущие несколько назначений) |

### 5.3 Идентификация и имена

- ID: `P` + 4 цифры (после `P9999` — 5 цифр), монотонно, **никогда не переиспользуется**.
- Имя папки: `P0007__kratkiy-slug` — латиница, цифры, дефис; slug ≤ 40 знаков; русское название живёт в `card.tsv`.
- Ссылки между протоколами — **по ID**, не по путям. Переименование папки связи не рвёт: индекс сопоставляет ID ↔ папка.
- Служебные папки зарезервированы префиксом `_`. Всё остальное в папке протокола — вложения Ти, столкновение имён невозможно.
- Контроль длины пути: программа предупреждает при приближении к лимиту Windows.

### 5.4 Запись

Атомарно: запись в `имя.tmp` → сброс на диск → переименование в целевое имя. Перед перезаписью — копия прежнего файла в `_history/`. Пропало питание посреди записи — целым остаётся либо старый файл, либо новый, но не половина.

### 5.5 Индекс

Производный, plain-text, **удаляемый**. Собирается сканированием `protocols/`. Полнотекстовый поиск — по `.md`, `.txt`, `.tsv`, `.csv` и именам вложений, с кэшем в памяти. Удалил `app/index/` — программа пересобрала, данные не пострадали.

## 6. Версии, конфликты, корзина, бэкап

### 6.1 Каждое сохранение

1. Сверить время изменения и хеш файла с тем, что было загружено в окно.
2. Скопировать текущий файл в `_history/<дата-время>__<причина>/`.
3. Записать новое атомарно.
4. Дописать строку в `journal.tsv`.

### 6.2 Конфликт (файл изменён извне, пока окно открыто)

1. **Активной становится более новая версия** по времени изменения.
2. **Старая молча прячется** в `_history/conflict-<дата-время>/`.
3. В карточке — неблокирующий значок «Спрятана версия от …». Открыть можно в любой момент: для текста — сравнение рядом, для бинарных файлов — обе копии.
4. «Вернуть» = сделать спрятанную версию новой активной; прежняя активная при этом тоже уходит в историю.

**Если время одинаковое или недостоверное** (флешка, сбой часов) — программа **не угадывает**: активной оставляет версию на диске, версию из окна прячет в конфликт, показывает значок. Решение за Ти, обе целы.

### 6.3 Прочие гарантии

- Удаление протокола → `trash/<дата-время>__P0007/` целиком, с вложениями и историей. Восстановление полное. Физическое уничтожение — только вручную, двойное подтверждение.
- Удаление вложения → `_history/`, не в небытие.
- `journal.tsv` только дописывается, никогда не переписывается.
- `.lock` с PID: второй экземпляр открывается только на чтение.
- Бэкап `backup/protfrg-<дата-время>.zip` — при первом запуске за день и перед массовыми операциями. Включает всё, кроме `backup/` и `app/index/`. **Автоудаление бэкапов и истории выключено по умолчанию.**
- Режим «только чтение» для портфеля на защищённой от записи флешке.
- Инструмент **«Проверка полноты»**: протоколы без назначения, без инструкций, без полей; битые ссылки `@file:` и `REF`; файлы вне протоколов; расхождения индекса.

## 7. Подбор протокола

- **Список / таблица** протоколов. Столбцы настраиваются из определений полей (`in_table`), сортировка по любому столбцу, у заголовков тоже есть ВП.
- **Фасетный отбор:** программа → бот → куда вставлять → метка → статус → вид. У каждого значения счётчик; комбинации без результатов не предлагаются — тупиков нет.
- **Мастер подбора «3 шага»:** для какой программы → для какого бота → куда вставлять. Основной сценарий, три клика.
- **Поиск `Ctrl+K`:** название, ID, значения любых полей, полный текст, имена вложений; учитываются `aliases` словарей.
- **Сохранённые критерии** (`criteria.tsv`) — частые отборы в один клик.
- **Копирование:** `Ctrl+Shift+C` — основное поле в буфер; `Ctrl+Alt+C` — по шаблону (например, инструкции + текст). Путь «нашёл → вставил в чат» — одно нажатие.
- **Карточка:** основное поле, назначение, инструкции, поля, вложения; предпросмотр `.md`, `.txt`, `.tsv`, `.csv`, `png/jpg/gif`; остальное — открыть внешней программой.
- **Флаг неполноты** виден в таблице, есть отдельный отбор «неполные».

## 8. Интерфейс

Одно главное окно: слева список/таблица и панель отбора, справа карточка, сверху поиск и мастер подбора, снизу строка состояния (путь портфеля, число протоколов, состояние индекса, значки конфликтов и бэкапа).

Отдельные окна: справка, история версий и сравнение, корзина, словари и определения полей, настройки, проверка полноты, бэкап/восстановление. **Все настройки — не уходя с окна**, где это возможно.

Горячие клавиши:

| Клавиши | Действие |
|---|---|
| `Ctrl+N` | новый протокол |
| `Ctrl+K` | поиск |
| `Ctrl+S` | сохранить |
| `Ctrl+Shift+C` | копировать основное поле |
| `Ctrl+Alt+C` | копировать по шаблону |
| `Ctrl+E` | править ВП элемента под курсором/фокусом |
| `F1` | справка по текущему элементу |
| `Ctrl+H` | история версий протокола |
| `Ctrl+D` | дублировать протокол |
| `Del` | в корзину |
| `Ctrl+B` | бэкап сейчас |
| `Esc` | закрыть всплывающее, отменить правку |

Все клавиши переназначаемы, таблица клавиш в справке генерируется автоматически.

## 9. ВП — всплывающие подсказки

- **Каждый** элемент интерфейса имеет `tip_id`: поля, кнопки, столбцы, флажки, заголовки, значки состояния.
- Заводские тексты — `app/tooltips.default.tsv` (только чтение). Правки Ти — `app/tooltips.user.tsv`, перекрывают поштучно. Обновление программы правки не затирает; «Сбросить к заводской» — поштучно.
- Состав ВП: `short` (при наведении), `long` (подробно), `keys` (клавиши), `help_id` (статья справки), `updated`.
- **Правка не уходя с окна:** навёл → `Ctrl+E` или значок «✎» в самой подсказке → всплывает inline-редактор рядом с элементом: кратко / подробно / клавиши / ссылка на справку, живой предпросмотр, `Сохранить` / `Esc` / `Сбросить`. Сохранение применяется мгновенно, окно не меняется, прежний текст ВП уходит в историю.
- Режим **«показать все ВП»**: у каждого элемента появляется значок правки — можно пройти экран подряд и заполнить всё.
- Отбор **«ВП не заполнена»** — дырки видны сразу; незаполненная ВП автоматически создаёт пустую запись.
- Раздел справки «Всплывающие подсказки» **генерируется из тех же TSV** — один источник истины, расхождений не бывает.
- Многострочность, простая разметка (жирный, список), настраиваемые задержка показа, длительность, размер шрифта.

## 10. Вложения

Любые типы и размеры, вложенные подпапки разрешены. Drag&drop в карточку = копирование в папку протокола, оригинал не удаляется. Действие **«Сделать основным полем / назначением / инструкциями»** превращает файл в источник через `@file:` без дублирования. Бинарные файлы программа не разбирает — только список, размер, дата, предпросмотр где умеет. SHA-256 в производном индексе — для поиска дублей. Основные форматы по назначению: текст в разных форматах, таблицы, схемы, чертежи, рисунки.

## 11. Справка внутри программы

Офлайн, встроена, и те же файлы читаются как Markdown на диске и на GitHub.

Разделы:

1. **Терминология** — единый язык, не менее 80 терминов, у каждого «что это» и «чем не является».
2. **Описание интерфейса** — статья на каждое окно, панель, поле, кнопку, столбец.
3. **Всплывающие подсказки** — автогенерация из TSV.
4. **Руководство пользователя** — подробнейшее, не менее 40 пошаговых сценариев, от «создать протокол» до «восстановить портфель из бэкапа».
5. **Форматы файлов и хранение** — дерево, схемы TSV, правила экранирования, что можно править руками.
6. **Версии и конфликты** — как прячется старое, как вернуть.
7. **Перенос и бэкап** — флешка, копирование, восстановление.
8. **Горячие клавиши** — автогенерация.
9. **Проверка полноты и диагностика** — что означают флаги и как чинить.
10. **FAQ** и **«Что делать, если…»** — разбор всех сообщений об ошибках.
11. **Заметки Ти** — `help/90-user/`, отдельная ветка, обновлениями не затирается.

Механика: `F1` с любого элемента → его статья и его ВП; дерево + полнотекстовый поиск по справке + закладки + перекрёстные ссылки; хлебные крошки; кнопка «править эту статью» (открывает `.md` как обычное поле с историей).

**Как обеспечить полноту и объём:** генератор каркаса проходит по всем определениям полей и всем `tip_id` и создаёт заготовки статей с пометкой «не заполнено». Инструмент **«Полнота справки»** показывает процент готовности по разделам. Пустых мест не остаётся по построению. Ориентир v1 — 300–500 тыс. знаков (≈ километр строки моноширинным 12 pt), дальше без потолка.

## 12. Настройки и переносимость

`app/settings.properties` (формат Java-native, ноль зависимостей), ключи:

```
ui.font_size, ui.theme, ui.table_columns
tip.delay_ms, tip.duration_ms, tip.font_size, tip.show_all
history.keep_forever=true
backup.on_first_start_of_day=true
backup.before_mass_ops=true
backup.keep_forever=true
search.fulltext=true
external.editor=
portfolio.readonly=false
```

Ни одной записи вне портфеля. Настройки переезжают вместе с папкой. Пути к внешним редакторам — единственное исключение, и оно необязательное.

## 15. Приёмка

1. Копирую портфель на флешку, запускаю оттуда — работает, следов в системе нет.
2. Кидаю `.md` в папку протокола → «Сделать основным полем» → текст в карточке, дубликат не создан.
3. Заполняю назначение: программы, боты, куда вставлять — тремя многозначными полями.
4. Мастер подбора в три клика находит нужный протокол среди 10 000.
5. `Ctrl+Shift+C` — текст в буфере, готов к вставке в чат.
6. Правлю ВП через `Ctrl+E` не уходя с окна — подсказка изменилась, окно то же, старая ВП в истории.
7. Правлю файл в Блокноте при открытом окне → новая версия активна, старая в `_history/`, значок есть, возврат работает.
8. Одинаковые метки времени → программа не выбирает молча, обе версии целы.
9. Убиваю процесс во время сохранения → данные целы.
10. Удаляю `app/index/` → пересобирается, ничего не потеряно.
11. Удаляю протокол → он в `trash/`, восстанавливается целиком с файлами и историей.
12. Добавляю поле строкой в `fields.tsv` → оно в карточке, таблице, отборе и справке.
13. Отбор «неполные» находит протокол без назначения; «ВП не заполнена» находит пустые подсказки.
14. `F1` с любого поля открывает его статью; поиск по справке работает.
15. Ни одного сетевого соединения за сеанс; ни одной записи в реестр.
16. Портфель открывается в Проводнике и на GitHub: `.md` читается, `.tsv` рисуется таблицей.

## 18. Задел на будущее

- **Несколько назначений** у протокола: столбец `use` в `_meta/fields.tsv` уже зарезервирован, формат не ломается.
- **Замена Swing на JavaFX**: слой `ui` изолирован от `core` и `storage`, замена не затрагивает данные.
- Экспорт выборки в TSV/CSV и в один сводный `.md`.
- Шаблоны копирования с подстановкой значений полей.
- Опциональное сжатие истории старше N дней в zip — только по явному включению.

## 19. Журнал решений

| № | Решение | Причина |
|---|---|---|
| 001 | файлы вместо БД | перенос копированием, читаемость, недоверие к БД |
| 002 | Swing, ноль зависимостей | входит в JDK, один jar, сборка без сети, долговечность |
| 003 | TSV + MD, не CSV/XLSX/реестр | табуляция не встречается в тексте, GitHub рисует таблицу, реестр не переносится |
| 004 | одно назначение + многозначные поля | закрывает сценарий, проще и надёжнее |
| 005 | всегда папка, служебное под `_` | один код-путь, любые файлы Ти без коллизий |
| 006 | новая версия активна, старая в `_history/`, при сомнении — обе | приоритет: нулевая потеря данных |
| 007 | имя Protfrg | имя не отражает назначение; совпадений не найдено |
